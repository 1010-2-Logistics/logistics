# 물류 관리 및 배송 시스템 (Sparta Logistics)

## 재고 차감 동시성 Jmeter Test 요약 보고서

### 테스트 조건
- 초기 재고: 100 
- 동시 요청 수: 100 
- 요청당 차감 수량: 1 
- JMeter Synchronizing Timer 사용 
- 기대 최종 재고: 0

### 개선 전

| 구분   | 동시 요청 수 | 평균 응답시간 |   오류율 | 기대 재고 | 실제 재고 |
  | ---- | ------: | ------: | ----: | ----: | ----: |
| 개선 전 |     100 |  121 ms | 0.67% |     0 |     2 |

100개의 차감 요청 이후 재고가 0이 되어야 하지만 2가 남아, 동시에 같은 재고를 수정하는 과정에서 일부 변경 내용이 유실되는 Lost Update가 발생함을 확인했다

##### 비관적 락 선택 이유
재고는 요청 충돌 시 성능보다 정확한 수량 유지가 우선되는 데이터이므로, 충돌 발생 후 처리하는 방식보다 재고 수정 시 해당 row에 락을 걸어 다른 트랜잭션의 접근을 대기시키는 비관적 락(PESSIMISTIC_WRITE) 을 적용했다



### 개선 후

| 구분   | 동시 요청 수 | 평균 응답시간 | 오류율 | 최종 재고 |
| ---- | ------: | ------: | --: |------:|
| 개선 후 |     100 | 1130 ms |  0% |     0 |

동일한 조건으로 재테스트한 결과 최종 재고가 기대값인 0과 일치하여, 동시 요청 상황에서도 재고 정합성이 보장되는 것을 확인했다

### 결과

비관적 락 적용으로 Lost Update 문제를 해결하고 재고 정합성을 보장할 수 있었다

다만 동일한 재고 row에 대한 요청이 락 해제를 기다리며 순차적으로 처리되기 때문에 평균 응답시간은 121ms -> 1130ms로 증가했다

따라서 이번 개선은 응답 성능보다 재고 데이터의 정합성을 우선한 선택이며 
추후 트래픽 증가 시에는 락 경합과 응답시간을 함께 모니터링할 필요가 있다
